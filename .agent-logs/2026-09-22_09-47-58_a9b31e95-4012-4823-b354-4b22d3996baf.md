Since this needs your Render account, here's the full walkthrough:

## 1. Create the service
1. Go to [render.com](https://render.com) → sign in (GitHub OAuth is easiest, since it can pull straight from your repo)
2. **New +** → **Web Service**
3. Connect your GitHub account if prompted, then select `AbdulRehman666/amazon_clone`

## 2. Configure the service
| Field | Value |
|---|---|
| Name | `amazon-clone` (anything) |
| Branch | `master` |
| Runtime | Node |
| Build Command | `npm install && npm run db:push && npm run db:seed && npm run build` |
| Start Command | `npm run start` |
| Instance Type | Free (see caveat below) or Starter |

## 3. Environment variables
Add these under the service's **Environment** tab:
- `DATABASE_URL` = `file:./prisma/dev.db`
- `AUTH_SECRET` = any long random string (e.g. generate one with `openssl rand -hex 32` or just mash the keyboard for 40+ chars)

## 4. Important caveat: free tier has no persistent disk

Render's **free** web services reset their filesystem on every redeploy and every time the instance spins down from inactivity — so the SQLite file (and with it, any accounts/orders created) won't survive. The build command above re-seeds the *product catalog* every deploy, so browsing/search always works, but sign-ups and orders made by a demo visitor could vanish on a restart.

For a submission demo this is usually fine (catalog always looks populated), but if you want accounts/orders to actually persist:
- Upgrade to a paid **Starter** instance and add a **Disk** (Render dashboard → your service → **Disks** → Add Disk, mount path e.g. `/opt/render/project/src/prisma`, 1GB is plenty)
- Then set `DATABASE_URL` to point at that mounted path, e.g. `file:/opt/render/project/src/prisma/dev.db`

## 5. Deploy
Click **Create Web Service** — Render builds and deploys automatically. You'll get a live URL like `https://amazon-clone-xxxx.onrender.com`.
